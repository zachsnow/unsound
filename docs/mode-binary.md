# --mode binary Implementation

## Overview

`--mode binary` compiles Unsound source code into a standalone native executable using Bun's `--compile` feature. The resulting binary includes:
- The Bun runtime
- The compiled program
- The Unsound interpreter (for runtime evaluation)

## Usage

```bash
# From source
echo '42' | bun cli.ts -m binary -o myprogram -
./myprogram  # outputs: 42

# From compiled usc binary
echo '"Hello!"' | ./dist/usc -m binary -o hello -
./hello  # outputs: Hello!
```

## How It Works

1. `generateStandalone()` creates self-contained JS that:
   - Imports `extension.ts` and `core.ts` directly (bundled by bun)
   - Includes the compiled program
   - Runs the program with the interpreter

2. `generateBinary()` writes the standalone JS to a temp file and runs `bun build --compile`

3. The resulting binary is fully self-contained - no external dependencies needed

## Implementation Details

### Embedded Sources

When the `usc` binary is compiled, all source files are embedded as strings in `embedded-sources.ts`. This file is auto-generated by `generate-embedded.ts`:

```bash
bun generate-embedded.ts  # Regenerate embedded-sources.ts
```

When `--mode binary` is invoked from a compiled `usc`:
1. Source files are extracted from `embeddedSources` to a temp directory
2. The standalone code imports from that temp directory
3. `bun build --compile` bundles everything into the final binary
4. Temp directory is cleaned up

### Key Design Decisions

1. **Direct imports for core**: The generated standalone imports `core.ts` directly rather than using `loadExtension()`. This ensures the core extension is bundled by bun and doesn't require runtime file access.

2. **Source embedding as strings**: Using `with { type: "file" }` import attribute conflicts with regular module imports of the same files. Instead, `generate-embedded.ts` serializes source files as template strings.

3. **Extension search paths**: When running from a compiled binary, extension search paths include the extracted temp directory.

## Building the usc Binary

```bash
# Generate embedded sources (run after modifying any .ts files)
bun generate-embedded.ts

# Build the binary
bun build --compile --outfile dist/usc ./cli.ts
```

## BUN_BE_BUN Feature

Compiled binaries include the full Bun runtime. Setting `BUN_BE_BUN=1` makes the binary act as the bun CLI:

```bash
BUN_BE_BUN=1 ./dist/usc --version  # Shows bun version
BUN_BE_BUN=1 ./dist/usc install    # Runs bun install
```

This requires Bun 1.2.16+.

## Limitations

- Custom `.ts`/`.js` extensions specified via `-x` are imported by absolute path, which won't work if the path doesn't exist on the target machine
- `.us` extensions work fine as they're compiled and inlined
